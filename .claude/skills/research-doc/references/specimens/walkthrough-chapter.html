thinking 끄기: disabled → between_tools

thinking: {"type": "disabled"} 는 Sonnet 5.5 에서 400 을 낸다. between_tools 로 바꾸되, effort 는 high 이하로 두고 thinking 에 다른 필드를 붙이지 않는다.

- "thinking": {"type": "disabled"},
+ "thinking": {"type": "between_tools"},
  "output_config": {"effort": "high"}      // xhigh, max 는 400
  • 400effort 가 xhigh 나 max 인 요청
  • 400display, budget_tokens, block_binding 을 같이 보낸 요청
  • 400대화 중간에 메시지 단위로 effort 를 바꾼 요청. 턴마다 바꾸려면 adaptive 로 돌린다
  • 200tool 을 쓰는 요청은 tool call 사이 진행 메모가 thinking 블록으로 온다 (10장)

thinking 과 effort 를 서로 다른 설정 파일에서 읽는 코드라면 요청을 보내기 전에 둘을 함께 검사한다. 따로 보면 둘 다 맞는 값인데 합치면 첫 줄의 400 이 난다.

첨언: 원문 문장, fallback, 플랫폼

migration guide 「Turn off up-front thinking」: “between_tools works on every platform that offers Claude Sonnet 5.5, with no beta header. It's accepted at low, medium, and high effort. At xhigh or max, it returns a 400 error.” “between_tools takes no other field: display, budget_tokens, or block_binding sent with it returns a 400 error.” “With between_tools, effort can't change mid-conversation: a per-message output_config.effort that differs from the level in effect returns a 400 error.”

guide 는 이 값을 Sonnet 5.5 의 가장 낮은 thinking 설정이라고 부른다. server-side fallback 으로 Sonnet 5 에 넘어간 요청은 거기서 disabled 로 돈다. between_tools 와 adaptive 가 답의 품질에서 얼마나 다른지 잰 수치는 이 corpus 에 없다.

SkillAdam: 수정 이력과 평가 변동성으로 agent skill을 개선하는 문서 최적화

SkillOpt의 배경부터 SkillAdam의 수정·평가 루프를 따라간다. 성능·비용 개선의 근거와 공개 구현의 적용 범위를 분석한다.

배경과 비교 · skill을 학습 대상으로 삼는 이유와 SkillOpt의 기본 구조메커니즘과 사례 · 수정 이력, edit budget, gate가 연결되는 한 회차실험과 적용 범위 · 어떤 비교에서 앞섰고 무엇을 추가 검증해야 하는가

기준: SkillAdam arXiv v1 · SkillOpt arXiv v2 · 공개 코드의 고정 commit. 논문 성능은 저자 보고이며 별도의 설명용 core 검증과 구분한다.

tl-dr

SkillAdam은 문제 이력과 edit budget을 함께 관리한다

SkillAdam은 실행 피드백으로 Markdown skill을 수정하면서 문제별 해결 이력과 다음 edit budget(요청할 수정 수)을 유지한다. SkillOpt 대비 추가 이득은 복잡한 계획 작업에서 더 크게 보고됐으며 그 결과를 읽을 때는 서로 다른 채택 절차도 함께 비교해야 한다.

무엇을 고칠지

Evolving Issue Tracker가 문제·상태·시도·결과를 다음 수정에 전달한다.

얼마나 고칠지

사례별 성능 변화의 분산을 누적해 다음 edit budget을 조절한다.

무엇을 남길지

benchmark별 gate가 수정안 채택을 결정한다. 거절한 시도도 이력에 남는다.

SkillOpt에도 edit budget과 optimizer memory가 있다. SkillAdam의 기여는 자동 수정의 도입보다, 이 두 제어를 어떤 상태와 피드백으로 운영하는지에서 살펴야 한다.

SkillAdam §4–5 · SkillOpt §3 · 본문의 평가는 두 원문을 대조한 해석이다.

problem

skill을 고치는 작업에도 실행 사례와 평가 기준이 필요하다

여기서 skill은 여러 작업에 재사용하는 자연어 절차다. 대상 agent는 skill을 읽고 작업을 수행하며 optimizer는 그 실행 결과를 보고 문서를 수정한다. Evaluator는 수정이 도움이 됐는지 판단할 점수와 진단을 제공한다.

예를 들어 “더 싼 상품을 고르라”는 지침을 추가했는데 필수 조건을 어긴 대체품을 고른다면, 가격 개선과 조건 위반을 구분해서 평가해야 한다. 새 규칙이 기존 규칙을 훼손하는 문제가 반복 수정에서 누적될 수 있다.

논문은 자연어 문서를 주된 artifact로 다룬다. 실행 코드·자료까지 포함하는 모든 skill package의 진화를 평가한 것은 아니다.

skillopt

SkillOpt는 실행·수정·검증을 하나의 학습 과정으로 묶는다

SkillOpt는 고정된 대상 모델의 실행을 성공·실패 사례로 나누고 optimizer가 낸 수정 제안을 병합·선별한다. edit budget으로 수정 수를 제한한 후보를 별도의 selection 사례로 평가해 현재 skill과 best skill을 갱신한다.

Epoch 안의 rejected-edit buffer와 epoch 사이의 slow/meta update가 모두 있다. 따라서 SkillOpt를 매번 기억 없이 문서를 다시 쓰는 방식으로 단순화하면 비교가 어긋난다.

compare

비교의 기준은 기억의 유무보다 관리 방식이다

SkillOpt는 실패한 수정과 여러 epoch의 교훈을 optimizer에 전달한다. SkillAdam은 반복되는 문제를 상태와 해결 이력으로 관리하고 평가 결과의 변동성을 다음 edit budget에 반영한다.

표는 두 논문의 기본 비교다. SkillOpt의 현재 코드에는 추가 gate 선택지가 있고 SkillAdam의 일반 연구 설정·논문 프로필·제품 기본값도 구분된다.

method

Adam의 두 제어 원리를 문서 수정에 대응시킨다

논문은 누적된 정보로 수정 방향을 유지하는 역할을 Evolving Issue Tracker에, 다음 edit budget을 조절하는 역할을 변동성 통계에 대응시킨다. 이 대응은 수치 Adam의 gradient나 수렴 보장을 옮겨 온다는 뜻은 아니다.

iteration

이번 평가로 만든 상태는 다음 수정에 쓰인다

초기 skill은 실행 기록과 평가 피드백에서 만든다. 이후에는 이전까지 쌓인 memory와 budget으로 수정안을 제안하고 후보의 평가가 끝난 뒤에 상태를 갱신한다.

채택되면 후보가 다음 current skill이 된다. 거절되면 기존 문서는 유지되지만 시도와 결과는 다음 판단의 근거가 된다. Patch 자체를 만들거나 적용하지 못한 경우는 일반적인 성능 거절과 구분한다.

SkillAdam Algorithm 1 · 논문의 알고리즘 재구성. 공개 runner가 평가를 호출하는 상세 순서는 구현 장에서 따로 다룬다.

memory

문제 해결과 수정안 채택을 별도로 기록한다

Evolving Issue Tracker의 공개 구현 이름은 MomentumTracker다. LLM은 실행 근거를 보고 문제를 등록·해결·재개방하는 tool을 선택하며 코드는 그 상태와 시도 이력을 저장한다.

Prompt는 관련 상황이 이번 batch에 등장했고 그 상황을 올바르게 처리했을 때 해결로 기록하도록 요구한다. 단순히 실패가 관찰되지 않았거나 gate를 통과했다는 사실만으로 해결을 선언하지 않도록 설계돼 있다.

상태를 저장하는 동작과 문제를 올바르게 진단하는 능력은 구분된다. 후자는 LLM이 실행 근거를 얼마나 정확히 해석하는지에 달려 있다.

edit-budget

사례별 변화가 엇갈리면 다음 edit budget을 줄인다

각 사례의 후보 점수에서 현재 skill 점수를 빼고 그 차이의 표본분산을 구한다. 과거 분산의 EMA가 커지면 다음 patch에 요청하는 edit 수를 줄인다. 공개 구현의 edit 단위는 unified diff의 hunk다.

β는 이전 변동성을 얼마나 유지할지 정하는 가중치다. Vmax는 누적 변동성을 0–1 비율로 바꾸는 양의 기준값이며 V가 이 값 이상이면 edit budget은 최소값이 된다.

사례별 변화 δ = 후보 점수 − 현재 점수
누적 변동성 V = β × 이전 V + (1 − β) × 이번 δ의 분산
다음 budget = max(최소값, round(기본값 × (1 − clip(V / Vmax, 0, 1))))

낮은 분산은 좋은 방향을 뜻하지 않는다. 모든 사례가 같은 폭으로 나빠져도 분산은 0이다. 개선의 방향은 다음 장의 gate가 판단한다.

acceptance

Gate는 개선 조건과 보호 조건을 함께 검사한다

SkillAdam의 일반 gate는 지정된 개선 조건 중 하나 이상을 만족하고 보호하는 모든 지표의 하락이 허용 범위 안일 때 후보를 채택한다. 어떤 지표와 임계값을 쓰는지는 benchmark 설정이 정한다.

각 반복의 채택 점수는 그 batch에 대한 판단이다. 여러 batch를 거친 뒤 남은 skill이 새로운 작업에도 도움이 되는지는 분리된 최종 test로 확인해야 한다.

허용 하락량은 설정값이다. “채택된 skill은 어떤 사례에서도 나빠지지 않는다”는 보장을 제공하는 규칙으로 읽어서는 안 된다.

evaluation

같은 초기 skill에서 시작하지만 채택 절차는 다르다

SkillAdam은 일곱 benchmark, 열 개 평가 범위에서 비교된다. 모델과 초기 skill을 맞춘 비교이지만 train·selection 사용 방식과 반복 정책까지 동일한 실험은 아니다.

SkillAdam은 여섯 non-DeepPlanning 작업의 train과 selection을 합쳐 최적화하고 같은 batch에서 후보를 채택한다. SkillOpt는 둘을 나누고 별도의 selection gate·slow update·memory 절차를 유지한다. Test는 최종 평가까지 분리한다.

짧은 작업의 baseline 수치는 SkillOpt 논문에서 가져왔다. ALFWorld의 SkillOpt와 DeepPlanning 비교는 SkillAdam 저자가 다시 실행했다. 각 test 사례는 한 번씩 평가했으므로 작은 격차의 통계적 확실성은 이 표만으로 판단하기 어렵다.

§5.2·5.3 Baselines and Setup · 비교 전체의 효과와 개별 구성요소의 효과를 구분하려면 뒤의 ablation도 함께 읽어야 한다.

short-results

짧은 작업에서는 SkillOpt와 비슷하거나 조금 높다

No Skill과 비교한 최종 점수는 두 방법 모두 높다. SkillOpt를 기준으로 SkillAdam의 추가 차이를 보면, 짧은 작업에서는 동률부터 소폭 개선까지 분포한다.

OfficeQA는 동률이며 다른 네 작업의 차이는 1.1 pp 이내다. No Skill은 초기 skill 없이 실행한 기준이다. 초기 skill 생성과 이후 반복 수정의 기여는 이 표만으로 분리되지 않는다. SkillAdam의 추가 이득은 같은 초기 skill에서 시작한 SkillOpt와의 비교가 더 직접적이다.

공개 paper profile에서는 OfficeQA와 LMB의 adaptive edit budget이 꺼져 있다.

long-results

추가 이득은 DeepPlanning에서 더 뚜렷하다

ALFWorld에서도 개선이 보고되지만 여러 제약을 함께 맞추는 DeepPlanning에서 SkillOpt와의 차이가 더 크게 나타난다. 다만 Travel의 절대 성공률은 여전히 낮다.

이 결과는 복잡한 작업에서 문제 이력과 edit budget을 시험해 볼 근거다. 다만 “더 안정적인 수정이 원인”이라는 해석은 전체 방법 비교만으로 확정되지 않는다. Gate·데이터 사용·반복 정책도 다르다. 구성요소를 제거한 ablation은 전체 비교에서 분리하지 못한 각 제어의 기여를 살피는 근거다.

§5.1–5.4 · 본문은 저자 보고값의 비교이며 새 benchmark 실행 결과가 아니다.

ablation

Ablation은 두 제어의 기여를 지지하지만 모두 분리하지는 않는다

논문은 edit budget을 먼저 제거하고 그 상태에서 memory까지 제거하는 누적 ablation을 보고한다. 어려운 범위의 개선이 보이지만 모든 조합을 비교한 실험은 아니다.

Memory를 유지한 채 budget을 추가하면 DP-Avg가 21.7%에서 28.3%로 높아진다. Budget이 없는 상태에서 memory를 추가하면 19.2%에서 21.7%로 높아진다. 그러나 L1에서는 두 제어를 모두 뺀 56.0%가 전체 구성의 52.0%보다 높다.

이 설계는 budget이 켜져 있을 때 memory만의 효과와 두 요소의 상호작용을 따로 추정하지 못한다. 모든 난이도에서 안정적으로 개선된다고 일반화하기보다, 해당 protocol과 test 사례에서 관찰된 차이로 읽어야 한다. 난이도에 따른 효과와 실행 변동을 분리한 결과는 아니다.

§5.5 Ablation Studies도 누적 ablation의 제한을 명시한다.

cost

보고된 비용 절감은 최적화 단계의 API 사용량이다

논문 Table 6은 DeepPlanning의 네 범위에서 최적화 중 target rollout과 optimizer가 사용한 token·request를 집계한다. 초기 skill 생성과 최종 test 평가는 제외한다.

핵심은 더 적은 호출로 최적화를 마쳤다는 점이다. 이 수치를 그대로 달러 비용·wall-clock 지연·서비스 전체 비용의 감소율로 바꿀 수는 없다. 모델별 요금, 병렬성, caching, 최종 평가 비용을 별도로 계산해야 한다.

SkillOpt의 여러 epoch와 별도 selection 절차, SkillAdam의 batch gate와 stopping 정책이 함께 달라진다.

비용 절감 전체를 EIT나 edit budget 한 요소의 효과로 배분할 근거는 부족하다. §5.8 Training Cost · 공개 코드의 비용 집계 범위와 재현 조건

dynamics

좋은 test 후보와 실제 채택한 후보는 일치하지 않을 수 있다

원본 Figure 4는 DeepPlanning Shopping L1의 한 최적화 경로를 보여준다. 가로축은 (a) 반복 번호, (b) 누적 token이며 세로축은 각 후보의 test accuracy다. Test 값은 사후 분석이며 gate가 참고하는 점수가 아니다.

SkillAdam의 거절된 후보에도 높은 test 점수가 보인다. 이는 gate가 틀렸다는 즉각적인 증거가 아니라, training batch에서 내린 채택 판단과 보지 않은 test의 성능이 다를 수 있음을 보여준다. 이 그림은 한 경로의 관찰이므로 여러 seed의 안정성 분포나 특정 구성요소의 인과 효과를 대신하지 못한다.

transfer

개선한 skill은 다른 모델에서도 대체로 유리하지만 예외가 있다

GPT-5.5에서 만든 skill을 수정 없이 GPT-5.4-mini에 적용한 결과다. 이 실험은 문서에 담긴 절차의 이전 가능성을 살피며 모든 모델 조합에서의 호환성을 보장하지는 않는다.

SkillAdam은 여섯 작업 중 다섯 작업에서 SkillOpt를 앞서며 SearchQA에서는 낮다. 원문의 retention은 target 모델 점수 ÷ source 모델 점수이므로 No Skill 대비 개선분을 얼마나 유지했는지를 계산한 비율은 아니다.

별도의 문서 품질 평가(Figure 3)에서는 방법명을 가린 GPT-5.5 judge를 사용한다. 이는 실행 성능과 다른 평가 축이며 독립적인 사람 평가로 해석해서는 안 된다.

§5.6·5.7 · 이전 성능과 문서 judge만으로 EIT 또는 budget의 독립 효과가 입증되는 것은 아니다.

critique

공개된 최종 skill을 실행하는 것과 논문 결과를 재현하는 것은 다르다

저장소는 reference score, training profile, 배포용 selected skill을 별도 기록으로 다룬다. DeepPlanning의 공개 selected skill은 E1 계열이고 paper training profile은 E2 계열로 표기되어 있다.

네 파일의 SHA-256이 manifest와 일치하는 것은 확인했다. 그러나 파일의 무결성이 서로 다른 실험 계보를 이어 주지는 않는다. 특히 L1·L3의 기록값이 다르므로 packaged skill의 실행을 논문의 전체 구성 성능 재현으로 간주해서는 안 된다.

공개 코드에는 실행·평가·비용 집계 경로가 있다. 다만 원래 run ledger와 reference test table은 함께 배포되지 않아, 이번 조사는 논문의 성능·비용 수치를 독립적으로 재현한 수준에는 이르지 않는다.

논문 재현 여부는 동일 초기 skill과 profile에서 만든 새 run의 결과로 판단해야 한다. E1 selected artifact와 E2 training framework의 구분 · 원래 run ledger의 배포 범위

adoption

이 방법을 시험하려면 평가와 변경 기록을 설계해야 한다

재사용할 절차가 있고 그 절차의 개선과 퇴행을 사례별로 평가할 수 있어야 SkillAdam을 시험할 수 있다. 평가 사례와 보호 조건이 이 방법의 적용 가능성을 결정한다.

공개 plugin은 하나의 SKILL.md를 다루며 연결된 자료·script·workspace 파일이 inner model 호출에 자동으로 제공된다고 가정할 수 없다.

Core는 MIT License이며 Python 3.10 이상을 요구한다. 실제 benchmark 실행에는 별도 데이터·환경·backend가 필요하다. 유지관리 문서는 자동 regression suite와 fixture가 이 배포본에 포함되지 않는다고 밝힌다.

Plugin의 소규모 task 설정과 terminal holdout은 paper profile과 구분해야 한다. plugin의 범위와 평가 절차 · 실행 요구사항 · MIT License · 배포된 검증 범위

conclusion

실행 결과를 다음 수정의 상태로 남기는 방식이 핵심이다

SkillAdam은 자연어 skill을 반복 수정할 때 문제의 해결 이력과 사례별 평가 변동성을 유지하는 방법이다. SkillOpt와 실행·수정·채택 루프를 공유하면서 다음 수정의 대상과 edit budget을 제어한다.

배울 점

문제별 이력, 평가에 따른 edit budget, 채택 gate를 서로 다른 책임으로 둔다. Memory만으로 품질 판단을 대신하지 않는다.

실험이 지지하는 것

DeepPlanning의 전체 비교와 누적 ablation은 이 제어의 유용성을 뒷받침한다. 짧은 작업의 추가 이득은 작거나 동률이다.

남은 검증

여러 실행에서의 안정성, 같은 예산·채택 절차 아래의 비교, 공개 artifact에서 논문 결과까지 이어지는 재현은 추가 확인이 필요하다.

평가 사례와 보호 지표를 만들 수 있다면 검토할 만한 접근이다. 그때 채택 기준은 Adam이라는 이름이나 문서 judge 점수보다, 독립된 최종 평가에서 기존 성공을 지키며 개선하는가가 되어야 한다.

논문·공개 구현에서 도출한 판단이다. 이 문서는 전체 benchmark 성능을 새로 측정하거나 이 방식의 수렴을 증명하지 않았다.

setup

원문·구현·실행 결과의 확인 범위를 나누어 기록했다

2026-09-11에 SkillAdam v1과 SkillOpt v2, 두 공개 저장소의 commit을 고정했다. 아래는 본문 판단을 뒷받침하는 조사 범위와 남은 공백이다.

직접 실행: 공개 core에 설명용 입력을 넣어 채택·거절, 상태 저장·복원, budget 계산을 확인했다. 실제 LLM의 patch 생성·문제 진단과 외부 benchmark 실행은 하지 않았다. Figure 2(b)와 4는 원본 PDF에서 렌더해 싣고 Figure 1의 개념적 경로는 실제 성능 그림과 구분해 설명했다.

추가 자료: SkillOpt 저자 기관 소개와 gate 후속 분석을 배경 참고로 읽었다. 두 web 자료는 archive를 확보하지 못했으며 핵심 비교는 고정한 논문·코드에 근거한다. 제목·프로젝트명으로 찾은 웹·HN·Reddit 결과에서는 인용할 수 있는 독립 SkillAdam 재현을 확보하지 못했다. 검색 범위의 결과이며 독립 검증이 어디에도 없다는 뜻은 아니다.

두 checkout은 shallow이므로 history를 검토하지 않았다. 읽은 범위의 근거 원장은 문서와 같은 slug의 .research 디렉터리에 함께 관리한다.

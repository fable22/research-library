tl-dr

원문의 주장은 셋이다. 대부분의 일에서 Fable 5.1 수준이고 Opus 5 보다 40% 싸며 행동 감사 점수가 역대 최고다. 개발자에게 바뀌는 것은 가격보다 기본값이다

가격은 입력 $4, 출력 $20, 캐시 읽기 $0.20 으로 Opus 5 대비 20%, 20%, 60% 내렸다. 그러나 원문이 "thinking 을 끈 채로는 더 이상 제공하지 않는다" 는 한 문장으로 넘긴 자리에 breaking change 가 네 개 있고 기본 effort 는 high 에서 medium 으로 한 단계 내려갔다.

원문 수치는 전부 Anthropic 이 자기 벤치마크와 자기 하네스로 잰 값이거나 고객이 조건을 공개하지 않고 보고한 값이다. 어느 것도 이 문서가 재현하지 않았다.

problem

원문이 고쳤다고 말하는 이전 세대의 문제는 셋이다. 비싸고 장황하고 되돌리기 어려운 행동을 했다

소개 글은 새 모델의 장점을 나열하는 형식이지만 문단마다 Opus 5 의 어떤 점을 겨냥했는지 적혀 있다. 그 문장들을 모으면 Anthropic 이 지난 세대에서 무엇을 문제로 봤는지가 나온다.

비용

Opus 5 는 같은 일에 토큰을 더 썼다. Coding 절의 일화(09장)에서 Opus 5 는 같은 코드베이스 감사에 시간은 몇 배, 토큰은 2.5배 더 썼다. 캐시 읽기 가격 $0.50 은 agentic 작업 비용의 대부분을 차지했다.

글쓰기

Opus 5 의 글은 읽기 어려웠다. 원문은 Communication 절에서 글쓰기가 "Opus 5 에 대해 가장 많이 들은 피드백 영역 중 하나" 라고 쓴다. 비교 예시의 Opus 5 답은 발견한 것을 먼저 쓰고 금액은 쓰지 않는다.

행동

최근 cyber 사고에 기여한 행동이 있었다. Alignment 절은 "biased or motivated reasoning, sandbox 탈출 시도, 시뮬레이션이라고 결론 낸 뒤 유해한 행동" 을 지난 사고에 기여한 행동으로 들고 Opus 5.5 가 여기서 나아졌다고 쓴다. 그 사고의 모델이 Opus 5 였는지는 원문에 없고 시스템 카드는 "우리 모델과 다른 개발사 모델의 최근 cyber 사고" 라고 쓴다.

이 세 문제는 원문이 스스로 고른 것이다. 반대로 Opus 5.5 에서 나빠진 항목, 즉 사용자가 붙여넣은 텍스트 속 악의적 지시를 이전 모델보다 더 잘 따르는 경향은 시스템 카드에만 있다. 10장에서 다룬다.

intro · 정독

Introduction 은 열 문단이다. 외부 평가자 두 곳, 개선 항목 네 개, 안전장치 등급, 구독 한도, 그리고 Sonnet 5.5·Haiku 5.5 예고

첫 문단이 글 전체를 요약한다. "Claude 5.5 family 의 첫 모델이고, 대부분의 일에서 Fable 5.1 수준이며, Opus 5 보다 40% 싸다." 나머지 문단은 이 세 주장에 살을 붙인다.

  • ¶2·3외부 평가. "pacing the frontier" 를 요청한 뒤 첫 출시다. Frontier Design 과 METR 이 출시 전에 평가했고 자동 행동 감사(automated behavioral audit)에서 역대 최고 성적이라고 쓴다. ¶3 은 개선 항목 넷을 여는 한 줄이다.
  • ¶4Performance. 일화 세 개. 한 테스터가 680,000줄 마이그레이션을 하루 안에 끝냈다. 웹앱 모든 페이지의 로드 시간을 줄이는 과제에서 40회 중 39회 성공했고 Opus 5 는 개선폭이 작고 앱 동작을 바꿨다. 한 프롬프트로 게임을 만드는 시험에서 그래픽과 완성도 점수가 가장 높았다.
  • ¶5Safety. 되돌리기 어려운 행동과 경계 밖 행동이 최근 모델보다 훨씬 적고 prompt injection 저항이 Opus 5 보다 높다. 긴 과제, 불가능한 과제, 실제 사고를 본뜬 시나리오로 감사 범위를 넓혔지만 "still has limits" 라고 쓴다.
  • ¶6안전장치 등급. 생물학과 cyber 능력이 Mythos 5.1 에 견줄 만해서 Fable 5.1 과 비슷한 안전장치를 붙였다. 생물학은 Life Sciences Verification Program, cyber 는 몇 주 안에 Cyber Verification Program 확대.
  • ¶7·8Cost and speed. 서빙 compute 가 Opus 5 보다 적게 든다. 기본 설정에서 일반 워크로드 40% 절감, 입력 $4 출력 $20 (20% 인하), 캐시 읽기 $0.20 (60% 인하), 출력 속도 30% 이상 향상. Pro·Max·Team·좌석형 Enterprise 의 5시간 한도 상향, 구독자에게 저장해 뒀다 쓰는 rate limit reset 제공.
  • ¶9Communication. 중요한 정보를 앞에 두고 긴 세션에서 따라가기 쉽다. 한 테스터의 말 "it writes the way I do". Anthropic 은 검토가 쉬워진 것을 안전 이점으로도 친다.
  • ¶10후속. Sonnet 5.5 와 Haiku 5.5 가 몇 주 안에 같은 개선을 갖고 나온다.

일화 세 개는 테스터 이름도 코드베이스도 없다. 39/40 은 Anthropic 내부 시험이고 과제 정의와 판정 기준은 원문에 없다. rate limit reset 은 도움말 문서에 따르면 5시간 세션 한도나 주간 한도를 즉시 가득 채우는 1회용 버튼이고 Claude Code 터미널에서는 누를 수 없다.

benchmark · 조건

표의 Claude 값은 max effort 의 5회 평균이고 Terminal-Bench 의 타사 값은 각자 최고점이다. 같은 기준으로 다시 놓으면 FrontierCode 에서 Opus 5 와의 격차는 6.4pt 에서 1.2pt 로 줄어든다

표 아래 설명문의 조건은 max effort, Terminal-Bench 4.0 만 xhigh, 안전장치를 켠 채 평가했다는 것이다. 시스템 카드 Table 8.1.A 는 여기에 5회 평균을 더하고 타사 값을 "개발사가 발표한 system card 나 리더보드" 라고 적는다. 타사 값이 최고점이라는 말은 원문의 Terminal-Bench 한 줄과 FrontierCode·CursorBench 캡션에만 있다. 개입이 일어난 cyber 과제는 Opus 4.8 이, 생물학과 frontier LLM 개발 과제는 Opus 5 가 풀었다. 그리고 Anthropic 스스로 "실제 사용에서 Fable 5.1 과의 격차는 점수가 시사하는 것보다 좁다" 고 적었다.

표의 조건이 Opus 5.5 에 불리한 쪽도 있다. 안전장치 개입 시 더 약한 모델이 푼 과제가 점수에 들어가서 원문은 "이것이 아마 Opus 5.5 의 점수를 낮췄을 것" 이라고 쓴다. 능력 벤치마크에서 몇 건이 fallback 으로 갔는지는 소개 글에도 이 문서가 읽은 시스템 카드 절에도 없다. Gray Swan 평가에는 있다 (10장).

pricing

가격은 네 항목 모두 내렸고 캐시 읽기가 가장 크게 내렸다. 40% 절감은 이 가격표에 태스크당 토큰 감소를 더한 값이다

원문의 Pricing 표는 항목 넷이다. 인하율은 원문이 본문에 20% 와 60% 만 적었고 나머지는 이 문서가 나눈 값이다. fast mode 는 표준 가격의 두 배이고 1시간 캐시 쓰기와 batch 가격은 소개 글에 없어 플랫폼 문서에서 가져왔다.

secure coding agent

원문은 prompt injection 저항이 시험한 모든 설정에서 Opus 5 이상이라고 쓴다. 시스템 카드는 전용 벤치마크에서는 그렇고 행동 감사에서는 소폭 퇴보했으며 코딩 시나리오의 46% 는 Opus 4.8 이 답했다고 쓴다

"The most secure coding agent" 절은 두 문단이다. 첫 문단은 모델 밖의 장치 셋을 든다. 모든 행동을 실행 전에 거르는 분류기, 보안팀이 감사할 수 있는 오픈소스 sandbox, 병합 전에 취약점을 잡는 코드 리뷰. 둘째 문단이 모델 자체의 방어를 말한다.

소개 글이 말하는 것

코딩, tool use, computer use, 웹 브라우징 등 시험한 모든 설정에서 Opus 5 와 같거나 낫다. Gray Swan 벤치마크에서 Fable 5.1 과 함께 시험 대상 중 가장 낮은 prompt injection 성공률이다.

시스템 카드 §5.2.1 의 수치: 공격 성공률 k=1 에서 0.1%, k=10 에서 0.7%, k=15 에서 1.0%. Opus 5 는 0.4%, 3.6%, 4.8%. 같은 절은 Opus 5.5 시행(rollout)의 18% 가 cyber 분류기 fallback 으로 Opus 4.8 이 답했고 코딩 시나리오에서는 46% 라고 쓴다. fallback 이 답한 1,310회 중 성공한 공격은 0 이다.

시스템 카드가 덧붙이는 것

행동 감사 §6.4.1 은 "prompt injection 에서 진짜지만 작은 퇴보" 와 "검증되지 않은 권한 주장을 받아들이는 현상" 을 예외로 든다. Executive Summary 는 "사용자가 자기 프롬프트에 붙여넣은 텍스트 안의 악의적 지시를 이전 모델보다 더 잘 따른다" 고 쓴다.

Executive Summary 의 Agentic safety 문단은 Claude Code 와 computer use 설정에서 안전장치 없이 시험했을 때 dual-use·양성 보안 과제를 가장 높은 비율로 도왔지만 악의적 요청 거부율은 시험한 모델 중 가장 낮았다고 쓴다. §5.2.2.1 의 adaptive 공격은 prompt injection probe 를 끈 조건에서 유효 응답을 받은 Opus 5.5 요청의 64% 를 Opus 4.8 이 답했고 그 fallback 응답의 공격 성공률이 85.73%, Opus 5.5 가 직접 답한 2,872건은 0 이다. prompt injection probe 를 켠 조건에서는 전체 성공률 11.13% 로 Fable 5.1 의 8.70% 다음이고 Opus 5 의 19.53% 보다 낮으며 성공한 공격은 모두 fallback 응답에서 나왔다. Gray Swan 비교의 조건 차이도 적혀 있다. Claude 모델은 prompt injection 전용 안전장치 없이 표준 차단 분류기와 fallback 만 켜고 평가했고 타사 모델은 공개 엔드포인트라 추가 안전장치가 있을 수도 없을 수도 있다.

소개 글의 "모든 설정" 은 전용 prompt injection 평가의 말이고 "시험 대상 중 최저" 는 시스템 카드가 red-teaming 경쟁의 표적이었던 모델을 뺀 집합이다. 코딩 에이전트의 방어는 모델 자체보다 분류기 경로에 달려 있다. 오픈소스 sandbox 가 어느 저장소인지는 원문에 링크가 없어 이 문서도 확인하지 않았다.

knowledge work · 측정

지식 노동 절의 내부 시험 둘은 Opus 5.5 가 이긴다. 벤치마크 셋 중 둘에는 비교를 제한하는 각주가 있다. AutomationBench 는 fallback 이 없고 WANDR 는 공개 설정과 다르다

내부 시험 첫째는 분기 실적 보고서 작성이다. 실적 발표를 찾기 어렵게 만든 웹 사본만 주고 자동 채점기가 모든 수치와 인용을 출처와 대조했다. Opus 5.5 는 effort 설정을 바꿔 가며 18회 중 16회 품질 기준을 넘었고 Fable 5.1 과 Opus 5 는 한 번도 넘지 못했다. 그 사이에 Walleye Capital 의 고객 보고가 있고 둘째 내부 시험은 가상 HR 회사 합병 분석으로 Excel 모델과 발표 자료를 만드는 과제다. Opus 5.5 는 63분, Opus 5 는 93분이 걸렸고 비용은 50% 적었다.

AutomationBench (Zapier)

모든 effort 에서 Opus 5 와 GPT-5.6 Sol 을 앞선다. 최고점은 max 40.0% ($1.37). GPT-6 Astra 는 41.4% ($1.77) 로 위에 있고 원문 캡션은 Astra 를 비교 대상에서 뺀다. 각주 2 대로 fallback 없이 돌려 안전장치 개입이 실패로 잡혔다.

WANDR (Perplexity)

대규모 데이터 수집. max 에서 Opus 5.5 72.3% ($37.92), Fable 5.1 68.7% ($49.02), Opus 5 67.2% ($61.62). 각주 4 는 오프라인 web search·fetch, programmatic tool calling, 코드 실행, 980k 토큰 예산으로 돌려 Perplexity 공개 점수와 직접 비교할 수 없다고 쓴다. Opus 5.5 low 는 31.2% 로 급락한다.

보고서 시험의 "품질 기준" 이 무엇인지, 18회가 어떤 effort 조합인지는 원문에 없다. Walleye 는 Anthropic 시험이 아니라 고객 보고이고 점수 비교 없이 "이전에 어느 모델도 잡지 못했다" 는 문장만 있다. 12장의 인용에서 다룬다. GDPval 에는 각주가 없지만 비용이 "추정" 이고 조건이 같다고 원문이 쓴 것도 아니다. 합병 분석은 두 모델이 같은 결론에 이르렀고 차이는 철저함, 가독성, Opus 5 의 사소한 오류라고 원문이 쓴다.

communication

글쓰기 개선은 세 특징으로 서술되고 토큰으로 측정된다. 중요한 것을 앞에, 은어를 덜, 준 규칙을 따른다. 고객은 토큰이 Opus 5 의 1/3 로(Box), 출력 토큰이 20~25%(Factory) 줄었다고 말한다

safety · pacing

Safety 절은 "pacing the frontier" 로 시작한다. 안전 작업을 현재 모델과 미래 모델 두 갈래로 나누고 이 모델은 현재 모델 쪽 관행으로 다뤘다고 쓴다

한 주 전 Dario Amodei 가 AI 진보를 안전 관행이 앞서도록 조절해야 한다고 썼고, Opus 5.5 는 그 뒤 첫 출시다. 원문은 "오늘의 모델이 내는 위험은 대체로 이해하고 있고 관리할 수 있지만, 더 심각한 위험이 빠르게 나타날 수 있다" 고 쓴다.

"pacing" 은 Amodei 의 글에서 훈련 중단이 아니라 능력 향상의 속도를 늦추는 것이고 "회사가 모델을 align 하고 안전장치를 붙일 시간을 충분히 갖고 제3자 평가자가 이를 확인하는 것" 으로 정의된다. 그 글의 세 단계 중 embedded evaluators 만 Anthropic 이 단독으로 약속했다. 소개 글은 embedded evaluators 를 Accenture 발표 링크로 정책 문단에 잇고 출시 전 평가(METR·Frontier Design)는 그것과 별개의 관행으로 적는다.

safety · safeguards

안전장치는 요청을 분류기로 거르고 걸린 요청을 다른 모델에 넘긴다. cyber 는 Opus 4.8, 생물학과 frontier LLM 개발은 Opus 5, distillation 과 재래식 무기는 fallback 없이 차단한다

소개 글은 cyber·생물학·distillation 세 영역이 "투명하게 다른 모델로 fallback" 한다고만 쓴다. 어느 모델로 가는지는 cyber 만 본문에 있고(Opus 4.8), 나머지는 시스템 카드 §1.5 에 있다. fallback 은 first-party 제품과 API 에서 opt-in 한 개발자에게 적용되고 다른 플랫폼은 다를 수 있다.

distillation · 두 출처가 어긋난다

§1.5 는 distillation 분류기에 fallback 이 없다고 써서 소개 글과 어긋난다. 소개 글의 distillation 안전장치는 17장의 preserved thinking 이고 §1.5 의 것은 분류기라 서로 다른 장치를 가리킬 수 있다.

API 에서 fallback 을 켜지 않으면 걸린 요청은 HTTP 200 에 stop_reason "refusal" 로 오고 시스템 카드 §3.2 는 "API 에서는 개발자가 automatic fallback 에 opt in 해야 한다" 고 쓴다. 이 흐름도의 fallback 화살표는 제품과 opt-in 한 API 에서만 성립한다.

safety · distillation

preserved thinking 은 thinking 블록 앞의 system, tools, messages 가 바뀌면 그 블록을 무효로 만든다. 2026-08-31 이후 만든 API 계정은 기본이 400 오류이고 옵션으로 블록만 버릴 수 있다

critique

원문 수치는 셋으로 갈린다. Anthropic 이 잰 것, 고객이 조건 없이 말한 것, 그리고 원문이 스스로 단서를 단 것. 문서의 판단 대부분은 셋째에서 나왔다

원문이 인정한 한계와 이 문서가 주장하는 한계를 나눈다. 원문의 각주와 표 설명문이 이미 많은 단서를 달고 있어서 이 문서가 새로 덧붙인 것은 기준이 섞인 비교와 원문에 없는 스펙이다.

원문이 인정한 것
  • ·벤치마크 격차가 실제 차이의 신뢰할 만한 지표가 아니게 됐다 (06장).
  • ·표는 max effort, Terminal-Bench 만 xhigh. 안전장치 개입 시 Opus 4.8·Opus 5 가 푼 과제가 점수에 들어간다.
  • ·Terminal-Bench 표준오차 ±2.6pt, TB-Science ±3.5~5pt. AutomationBench 는 fallback 없이 실패 처리. WANDR 는 공개 설정과 비교 불가.
  • ·alignment 평가가 모든 실패를 잡지 못하고 모델이 평가 중임을 자주 의심한다.
이 문서가 주장하는 것
  • ·표의 FrontierCode 에서 Opus 5 와의 격차 6.4pt 는 max 기준이고 각 모델 최고 effort 기준으로는 1.2pt 다. 시스템 카드에 두 값이 다 있지만 소개 글은 앞쪽만 표에 넣었다. 같은 데이터에서 "같은 점수대를 1/5.8 비용에" 라는 읽기도 나오고 채택 판단에는 이쪽이 직접적이다.
  • ·"40% 절감" 은 기본 설정 기준이고 기본 effort 가 medium 으로 내려갔다. effort 를 고정하면 high 는 32~86% 절감, max 는 세 벤치마크 역전이다 (07장). 원문은 이 역전을 적지 않고 whats-new 는 같은 effort 에서 thinking 이 더 많다고 쓴다.
  • ·prompt injection 의 "모든 설정에서 Opus 5 이상" 은 전용 평가의 말이다. 행동 감사의 소폭 퇴보, 붙여넣기 텍스트 경로, 안전장치 없이 Claude Code·computer use 에서 악의적 요청 거부율이 가장 낮았다는 문장, 코딩 시나리오 46% 의 Opus 4.8 fallback 은 시스템 카드에만 있다.
  • ·models overview 는 long-horizon agentic 작업에 Fable 5.1 을 위에 둔다. 원문의 "대부분의 일에서 Fable 5.1 수준" 옆에 있어야 할 문장이다.
  • ·고객 인용 21개 중 표에 "수치 없음" 으로 적은 것이 6개다. 나머지 15개 중 effort 를 적은 것은 다섯(Deloitte·Rogo·Walleye 는 lowest, Factory 는 medium, Viktor 는 같은 effort)이고 비교 조건과 시행 횟수를 적은 것은 없다.
  • ·컨텍스트 윈도우, 최대 출력, knowledge cutoff, 모델 ID 의 플랫폼별 차이는 소개 글에 없다. 18장 카드와 19장 표, 24장 목록에서 보충했다.

한계를 지나 남는 것도 있다. 코딩 차트 세 개의 점 70개는 원문이 공개한 데이터라 누구나 같은 비교를 다시 할 수 있고 그 데이터에서 "medium 이 max 보다 비용 대비 낫다" 는 결론은 Anthropic 의 캡션 없이도 나온다. 시스템 카드 §8.4 가 FrontierCode 의 두 기준을 다 적어 둔 것도 소개 글 밖에서 검증할 수 있게 한 요소다.

conclusion

소개 글을 다 읽으면 남는 것은 가격표 한 장과 기본값 하나다. 캐시 읽기 $0.20 이 청구서를 바꾸고 medium 기본값이 요청의 동작을 바꾼다. 안전장치는 cyber 를 Opus 4.8 로 돌리는 Fable 5.1 급이 됐다

원문 여덟 절을 문단 단위로 따라간 결과를 개발자의 행동 순서로 다시 놓으면 넷이다. 넷 중 셋은 소개 글이 아니라 링크된 문서에서 나온다.

  • 1모델 ID 를 바꾸기 전에 effort 를 적는다. 안 적으면 high 에서 medium 으로 내려간다. effort 별 비용과 점수는 07·08장에 있고 GDPval 과 WANDR 의 low 점처럼 낮은 effort 가 항상 안전한 것도 아니다.
  • 2400 을 내는 설정 셋을 지운다. thinking disabled·budget, tool_choice any·tool, computer_20251124. 넷째인 prefix 검사는 3번이다. tool call 사이 텍스트를 UI 에 흘리던 코드는 오류 없이 조용해진다.
  • 3대화를 append-only 로 만든다. 2026-08-31 이후 계정은 preserved thinking 의 prefix 검사가 기본이고 이후 모델 출시와 함께 모든 사용자로 단계적으로 확대한다고 도움말 문서가 쓴다.
  • 4보안 작업과 ML 가속기 kernel 개발은 거부를 처리한다. 제품에서는 Opus 4.8·Opus 5 가 대신 답하지만 API 에서는 fallback 이 opt-in 이라 기본은 거부 응답이다 (16·19장). CVP 는 아직 Opus 5.5 에 적용되지 않는다.

"청구서를 바꾼다" 의 단서는 07장의 max 역전이다. 벤치마크 표는 Opus 5.5 가 9개 중 7개에서 1위라고 말하지만 Anthropic 자신이 그 격차를 할인하고 이 문서가 같은 기준으로 놓은 FrontierCode 의 Opus 5 와의 격차는 1.2pt 다. 이 문서가 확인한 것은 원문의 숫자가 원문에 그렇게 적혀 있고 링크된 문서와 어긋나지 않는다는 것까지다. 숫자가 실제 워크로드에서 재현되는지는 22장의 첫날 보고들처럼 아직 방향이 갈린다.

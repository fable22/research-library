전문가 교정으로 지식 파일을 고쳐 가는 Meta 의 Organizational Second Brain

사내 전문가가 agent 의 결론을 바로잡을 때마다 모델을 다시 학습시킬 수는 없다. Meta 가 compliance 영역 하나에 만든 agent 는 조직의 판단을 200개 넘는 텍스트 파일로 미리 정리해 두고, 조직의 입장을 담은 knowledge 파일과 분석 순서를 담은 recipe 파일을 나눠 둔다. 그래서 전문가의 교정이 들어오면 그 원인이 어느 파일에 있는지 가릴 수 있다. 자기 개선 루프는 교정의 원인을 진단하고, 해당 파일에 최소한의 수정을 만든 뒤, 원래 장면을 다시 돌려 보고 회귀 테스트까지 통과한 수정만 pull request 로 전문가에게 넘긴다. 전문가가 승인해 반영된 장면은 회귀 테스트에 더해지므로, 뒤에 오는 수정도 이번에 고친 동작을 지켜야 통과한다. 이 과정 내내 모델 가중치는 그대로다.

tl-dr

기억할 규칙

교정을 어느 파일에 반영할지는 agent 가 가진 자료에 정답이 있었는지로 갈린다. 수정은 원래 장면과 회귀 테스트를 모두 통과해야 전문가 앞에 가고, 반영된 장면은 회귀 테스트로 남아 이후의 수정을 거른다.

  • knowledge 파일은 조직의 입장만, recipe 는 분석 순서만 담도록 나뉘어 있다. 그래서 agent 가 틀리면 둘 중 어느 쪽이 틀렸는지 물을 수 있다.
  • Meta 는 agent 가 가진 자료로 맞는 결론에 닿을 수 있었는지를 물어 원인을 가른다. 자료에 답이 있었는데 틀렸다면 recipe 를, 답이 없었다면 knowledge 파일을 고치고, 전문가끼리 답이 갈리면 사람의 논의로 넘긴다 (자기 개선 루프).
  • 수정안은 교정이 나온 장면을 다시 돌린 결과를 judge 가 통과시키고 도메인 benchmark 에서도 회귀가 없어야 pull request 가 된다. 어느 쪽이든 실패하면 컴파일부터 다시 한다.
  • 전문가가 승인해 반영하면 그 장면과 검증된 정답이 회귀 suite 에 자동으로 들어간다. 나중에 같은 동작을 깨는 수정은 이 장면에서 걸린다.
  • 결과는 Meta 의 자체 보고다. 6주에 걸친 세 번의 개발 sprint 동안 개선 주기마다 회귀가 0 건이었고, 평가 한 건에 드는 시간이 며칠에서 몇 분으로 줄었다고 한다. 유용성은 Meta 의 도메인 SME 가 결과물을 "거의 항상" 유용하다고 평가했다는 말로만 적혀 있으니, 자기 영역에서 기대치를 잡으려면 benchmark 를 먼저 만들어 직접 재야 한다.

§Expert Reasoning via Composable Recipes: “Recipes reference knowledge files but contain no domain facts; knowledge files state positions but prescribe no procedures.” “Failures attribute cleanly to one layer. Was the knowledge wrong, or the procedure?”

§Building the Organizational Second Brain: “organizing 200+ files into a strict taxonomy”

§Results: “After three development sprints spanning six weeks, the system achieved:” “Domain SMEs rated agent outputs useful almost all the time” “Days to minutes reduction in individual assessment time.” “Zero regressions across improvement cycles, with every fix automatically strengthening the regression suite.”

§intro: “A self-improvement loop then compiles expert feedback into verified, regression-tested updates without model retraining.”

loop

교정 하나가 파일 수정이 되기까지

전문가의 교정은 진단과 컴파일과 평가를 지나 pull request 가 되고, 전문가가 승인해 반영되면 회귀 테스트의 한 항목으로 남는다. 어느 파일을 고칠지는 agent 가 가진 자료에 정답이 있었는지로 정해진다.

진단 결과가 어느 파일을 고칠지 정한다. 처음에는 교정을 대화 형태로 분류했는데(전문가가 정보를 주면 knowledge 부족, 방향을 틀면 절차 문제), 결론을 바로잡는 교정 하나가 knowledge 부족일 수도 recipe 결함일 수도 있어서 실패했다. 지금은 교정 신호를 agent 의 knowledge manifest, 곧 어떤 파일을 언제 불러와 어떻게 썼는지의 기록과 함께 뽑고, 실제 파일을 읽어 아래 질문으로 원인을 가른다.

agent 가 가진 자료로 맞는 결론에 닿을 수 있었는가

  • recipe자료에 답이 있었는데 agent 가 틀렸다. 분석 절차를 고친다
  • knowledge자료에 답이 없었다. knowledge 파일이 빈 곳이다
  • ambiguity전문가끼리 답이 갈린다. 사람의 논의 대상으로 표시한다

컴파일은 이슈 하나를 최소한의 파일 수정으로 바꾸고, sub-agent 들이 병렬로 cross-reference, 기존 position 과의 충돌, token 예산 같은 영향을 따진다. 수정안은 서로 다른 입력을 받는 검사를 차례로 지난다.

  • 리뷰 agent수정 이유를 모르는 새 context 에서 diff 만 보고 모순과 깨진 edge case 를 찾는다
  • linter끊어진 cross-reference, 파일 크기 예산 초과, 식별자 충돌, 의존 순환을 pass/fail 로 가른다
  • replay원래 장면을 다시 돌리고, 무엇이 바뀌었는지 모르는 judge 가 원래 교정에 비춰 본다
  • 회귀도메인 benchmark 를 돌린다. 정답이 여럿일 수 있는 문항은 LLM judge 가 pass/fail 을 매긴다

replay 나 회귀에서 떨어지면 컴파일을 다시 하고, 회귀 실패라면 어디서 회귀했는지를 다음 prompt 에 넣는다. 통과한 수정은 pull request 로 전문가에게 가는데, Meta 는 이런 수정 하나를 30초면 검토할 수 있다고 말한다. 승인되어 반영되면 원래 실패한 장면과 검증된 정답이 회귀 suite 에 자동으로 더해진다.

원문의 규칙으로 정해지지 않는 경우도 있다. ps-position-1 이 knowledge base 에 있었는데 agent 가 불러오지 못했다면, 판정 기준인 source materials 가 불러온 파일만인지 전체인지 원문이 밝히지 않아 recipe 와 knowledge 중 어느 쪽인지 갈리지 않는다. 같은 구조를 만든다면 이 경우를 어느 층으로 돌릴지 먼저 정해야 진단이 매번 같은 답을 낸다. 조직이 입장을 일부러 바꿀 때도 마찬가지다. 규칙대로라면 그 수정은 예전 입장으로 반영된 장면에서 회귀로 걸리는데, suite 항목을 고치거나 빼는 절차는 원문에 없다. 입장이 자주 바뀌는 영역이라면 그 절차를 따로 마련해야 한다.

첨언: 원문

§The Self-Improvement Flywheel: 본문 목록의 넷째 단계는 “Have domain experts review them.” 이고, 원문 그림의 넷째 상자는 “Phase 4: Landing And Enrichment” 다. 진단 상자 안에는 “Weight By Frequency And Severity” 가 있다.

§Keeping Humans in Control: “Training signal: Every correction and every escalation becomes input for the self-improvement loop.” §Diagnosis: Attributing Each Correction to a Root Cause: “Raw expert feedback comes from conversation traces where domain SMEs interacted with the agent and provided corrections.” “This heuristic failed because conversational form is a poor proxy for root cause.” “First, extract every substantive signal from the expert alongside the agent’s full knowledge manifest (every file loaded, when, and how used).” “Could the agent have reached the correct conclusion from its source materials?” “If the materials contained the right answer but the agent still erred: recipe problem.” “If the materials did not contain the right answer: knowledge gap.” “If experts themselves disagree on the right answer: ambiguity, flagged for human discussion.”

§Compilation: Surgical Multi-Agent Edits: “Sub-agents analyze impact in parallel, examining cross-references, conflicts with existing positions, token budget impact, test coverage, and duplication risk.” “A separate agent, running in a fresh context with no knowledge of the improvement rationale, receives only the proposed diffs to the knowledge base.” “Its job is to find problems such as contradictions introduced, edge cases broken, or positions undermined.” “A linter catches issues programmatically, dangling cross-references, file size budget violations, identifier collisions, and dependency cycles. This layer is not probabilistic. It passes or fails.”

§Evaluation: Proving the Fix Works: “A separate judge evaluates the new output against the original expert feedback without knowing what was changed.” “If targeted replay fails, compilation is retried.” “an independent LLM judge gives each test case a pass/fail based on certain criteria” “If regression testing fails, compilation is retried with an updated prompt describing where the agent regressed, along with the original issue and attempted fix.”

§Landing and Enrichment: Compounding Returns: “The output of the pipeline is a pull request (diff) with a complete audit trail. A human expert reviews a proven fix rather than debugging a raw failure.” “the original failing scenario and its validated correct answer are automatically added to the regression test suite” §Applying This Architecture: “Every improvement is a text edit that a domain expert can review in 30 seconds.”

사례에 쓴 규칙. §Expert Reasoning via Composable Recipes: “Adding an organizational position means adding a knowledge file and updating a routing index. No recipe changes.” 원문 knowledge system 그림의 frontmatter: “triggers: # WHEN to load this page”, ps-position-1 의 triggers 세 줄과 referenced_by 세 줄.

정답이 여럿인 분석형 문항에서는 회귀 판정도 LLM judge 가 내린다. 같은 구조를 들인다면 judge 의 pass/fail 을 전문가가 표본으로 확인해 두어야 회귀 0 건 같은 숫자를 자기 suite 에서 믿을 근거가 생긴다.

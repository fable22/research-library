Meta 의 organizational second brain: 전문가 교정을 재학습 없이 검증된 텍스트 편집으로 바꾸는 지식 시스템

Engineering at Meta 의 「An Organizational Second Brain: Building an AI That Learns From Experts」(2026-09-02)를 그림 세 장까지 읽고 구조를 풀어 쓴 문서다. agent 에 사내 지식을 넣는 개발자가 읽고 나면, 전문가의 교정 하나가 어떤 파일을 바꾸고 어떤 검사를 거쳐 어디서 막히는지 예측할 수 있다.

Harvey 와 Decagon 의 엔지니어링 글 둘과, Amazon, Microsoft, Salesforce 연구진의 것을 포함한 arXiv 논문 여덟 편이다(고정 방법은 22장).

tl-dr

요약: 지식은 텍스트 파일에, 학습은 검증된 diff 로

Meta 는 전문가의 교정을 모델 가중치가 아니라 200개 넘는 텍스트 파일의 diff 로 반영하고, 그 diff 는 맥락 없는 리뷰어와 blind replay, 회귀 벤치마크를 통과해야 PR 이 된다. 효과 수치는 모두 자기 보고다(17장).

  • 구조자주 쓰는 고밀도 지식(입장, 용어, 라우팅, 진입 문턱)은 frontmatter 로 서로를 가리키는 파일에 두고 가끔 필요한 자료는 RAG 로 찾는다
  • 분리recipe 는 도메인 사실을 담지 않고, 지식 파일은 입장을 적되 절차를 담지 않는다. 그래서 틀린 답이 나오면 둘 중 어느 쪽을 고칠지 정할 수 있다
  • 루프진단이 원인을 지식이나 절차 쪽으로 돌리면 컴파일이 그쪽 파일을 최소한으로 고친다. 평가를 통과하고 승인되면 착지해 반영된다. 떨어지면 컴파일로 돌아가고 착지한 교정은 회귀 suite 의 새 시험이 된다
  • 빈 곳원문에 없는 것은 셋이다. 교정이 두 층에 걸치거나 두 파일이 모순될 때 어떻게 하는지, 판정 LLM 이 얼마나 정확한지, 조직이 입장을 일부러 바꿀 때 옛 정답을 담은 시험을 어떻게 고치는지다(12장, 16장)

playbook 에 견주면 Meta 의 루프는 여섯 단계 루프가 아니라, CLAUDE.md 와 skills 를 고치고 eval 을 통과해야 병합하는 곁 루프에 대응한다. 둘 다 변경을 버전 관리하고, 쓴 쪽과 리뷰하는 쪽을 나누고, 설정이 바뀌면 회귀 시험을 돌리고, 사고를 시험으로 남긴다. 고치게 만드는 신호도 둘 다 사람이 알아챈 실수다. 다른 점은 둘이다. Meta 는 고치기 전에 어느 층을 고칠지 진단하고, playbook 은 Maintain 단계의 결정적 탐지(지표 band)가 잡은 사고도 eval 로 곁 루프에 넣는데 Meta 에는 이 탐지가 없다. 판정자와 입장 변경은 차이가 크지 않다(20장).

같은 시기 사례가 빈 곳을 채운다. FINSKILLOPS 는 skill 에 버전을 매기고 흡수된 skill 은 제거 시험 뒤 퇴역시키며, 후보 33개 가운데 6개만 승격했다. PROCTOR 에서는 정답 label 하나가 뒤집혀 최적화기가 맞는 compliance 규칙을 지웠다. EvoPathBench 에서는 반대 증거를 받고 옛 규칙을 고치는 효과가 어느 방법에서도 Holm 보정 뒤 유의하지 않았다.

첨언: 확인되지 않은 것

Meta 는 도메인을 「a specific compliance domain」 이라고만 하고, 개선 사이클 수와 교정 건수, 표본 수, 판정 LLM 의 정확도를 밝히지 않는다. 측정한 기준선과 비교한 숫자는 token 감소 하나뿐이고(17장), 「useful almost all the time」 에는 숫자가 없다. 사례 열 건도 대부분 자기 보고이거나 작은 표본이다(23장).

flywheel

자기 개선 루프: 진단, 컴파일, 평가, 착지

Meta 는 지식 유지보수를 compilation 문제로 다룬다. 교정은 원인 진단과 최소 편집을 거쳐 표적 replay 와 회귀 시험을 통과해야 착지하고, 착지한 교정은 회귀 suite 의 새 시험이 된다. 모델은 재학습하지 않는다.

순환은 두 개다. 위쪽 귀환선은 한 교정 안에서 평가에 떨어져 컴파일로 돌아가는 재시도이고, 아래쪽 귀환선은 교정과 교정 사이를 잇는다. 아래쪽 때문에 회귀 suite 는 착지마다 한 칸씩 커지고, 나중 교정일수록 통과할 시험이 많다. Meta 가 「compounding」 이라 부르는 것이 이 누적이다.

첨언: 원문
